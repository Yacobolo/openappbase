# Project Context

## Purpose
PostgresUI is an open-source nocode Postgres builder inspired by NocoDB and Airtable. It enables simple CRUD apps directly on PostgreSQL with a server-rendered UI (Templ) and reactive updates via Datastar/SSE. This repository is bootstrapped from the Northstar template, so some "Northstar" references remain and will be renamed as the project evolves.
- Nocode CRUD: browse, filter, and edit rows on existing tables
- Schema explorer: view schemas, tables, and columns
- Editor: spreadsheet-like table view with resizable columns
- Live updates: planned via PostgreSQL LISTEN/NOTIFY bridged to SSE

## Tech Stack
- Server (Go 1.25)
  - HTTP router: `github.com/go-chi/chi/v5`
  - Sessions: `github.com/gorilla/sessions`
  - Logging: `log/slog`
  - Concurrency: `golang.org/x/sync/errgroup`
  - Config: build-tagged `dev`/`prod` + `.env` via `github.com/joho/godotenv`
- Data
  - PostgreSQL via `github.com/jackc/pgx/v5` and `pgxpool`
  - Query layer generated by sqlc (`internal/store/query.sql`, `query.sql.go`)
  - Realtime DB events: PostgreSQL LISTEN/NOTIFY (planned)
- Realtime / State
  - Embedded NATS Server with JetStream (`github.com/delaneyj/toolbelt/embeddednats`)
  - JetStream Key-Value for per-session feature state
  - Datastar SSE for hot reload and reactive updates (`github.com/starfederation/datastar-go`)
- Frontend
  - Server-side templates: `templ` (.templ → `*_templ.go`)
  - Styling: TailwindCSS + DaisyUI (built via `gotailwind`)
  - Static bundling: esbuild (custom TS entrypoints under `web/libs`)
  - Web Components: vanilla custom elements; optional Lit setup
- Build/Dev Tooling
  - `Taskfile.yml` tasks for build, live reload, debug
  - Live reload: Air + templ watch + Tailwind watch + esbuild watch
  - Asset embedding: `hashfs` in prod; direct file serving in dev
  - Dockerfile for container builds

## Project Conventions

### Code Style
- Go
  - Standard `gofmt`/`go vet` practices; small, focused packages
  - `slog` for structured logging and consistent levels
  - Environment via `config` package; `dev`/`prod` build tags determine behavior
- Templ
  - Source files use `.templ`; generated code is `*_templ.go`
  - Keep components small and feature-scoped; no inline business logic
- Naming
  - Feature folders are lowercased (e.g., `explorer`, `editor`)
  - Generated files never edited by hand (`*_templ.go`, sqlc outputs)
- Config
  - Required env: `CONNECTION_STRING`
  - Optional env: `HOST` (default `0.0.0.0`), `PORT` (default `8080`), `SESSION_SECRET` (default `session-secret`), `LOG_LEVEL` (`DEBUG|INFO|WARN|ERROR`), `NATS_PORT` (Taskfile default `4222`)
- Template provenance
  - This codebase started from the Northstar template; references to "northstar" in module/package names are expected and benign.

### Architecture Patterns
- Feature-first organization under `internal/features/<feature>`
  - `pages/` and `components/` contain Templ views
  - `handlers.go` contains HTTP handlers
  - `services/` encapsulate business/domain logic and dependencies (db, NATS)
- Routing
  - Central setup in `internal/router.go` configuring static handlers and feature routes
  - `chi` router with middleware: logger + recoverer
- Static assets
  - Dev (`-tags=dev`): served from disk (`web/resources/static_dev.go`)
  - Prod (default): embedded via `hashfs` (`web/resources/static_prod.go`)
- State management
  - Per-session feature state using a generic `StateStore[T]` backed by JetStream KV (`internal/session/store.go`)
- Data access
  - `internal/store`: `pgxpool` connection (`connection.go`), sqlc-generated queries and models, hand-authored SQL in `query.sql`
- Realtime updates (planned)
  - Database change propagation via PostgreSQL LISTEN/NOTIFY, bridged to clients with Datastar SSE

### Testing Strategy
- Unit tests (recommended)
  - Services (e.g., `ExplorerService`) with a test pgxpool against a disposable Postgres
  - Handlers via httptest for route-level behavior
- Integration tests (recommended)
  - Spin up Postgres (Docker) and run sqlc queries end-to-end
  - Optionally start embedded NATS and validate KV-backed session state
  - For LISTEN/NOTIFY, verify event flow to SSE endpoints (when implemented)
- View tests (lightweight)
  - Templ compilation in CI to catch template errors
- Linting/formatting
  - `go vet`, `gofmt -s`, and staticcheck (optional) in CI

### Git Workflow
- Branching: feature branches off `main` (e.g., `feat/explorer-columns`)
- Commits: conventional style preferred (feat, fix, refactor, chore, docs)
- Reviews: PRs required for meaningful changes; small, focused diffs
- Specs: use OpenSpec for non-trivial/new capabilities; validate with `openspec validate --strict` before implementation

## Domain Context
- Core entities (`internal/domain/schema.go`)
  - `Schema`: name, tables
  - `Table`: name, owner, row security flag, estimated rows
  - `Column`: name, data type, nullability, default
- Explorer service (`internal/features/explorer/services/explorer_service.go`)
  - Builds schema overview from sqlc query `GetFullSchemaDetails`
  - Retrieves columns via `GetTableColumns`
  - Maintains per-session active schema/table in JetStream KV
- Editor feature
  - Spreadsheet-like presentation with resizable columns (`internal/features/editor/components/datatable.templ`)
- Planned nocode capabilities
  - Views on tables/queries, simple forms, computed fields, and row-level actions akin to Airtable/NocoDB

## Important Constraints
- Environment
  - `CONNECTION_STRING` is required; app exits if missing
  - Build tags control behavior: `dev` (direct static serving + hot reload endpoint), `prod` (embedded assets)
- Ports
  - HTTP: `HOST:PORT` (default `0.0.0.0:8080`)
  - NATS: auto-selected free port; can be overridden by `NATS_PORT`
- Database events (planned)
  - Postgres must allow `LISTEN/NOTIFY` for realtime; otherwise fallback polling may be needed
- Generated code
  - Do not edit sqlc outputs (`internal/store/*.go`) or Templ-generated files (`*_templ.go`)
- Browser/runtime
  - Some UX relies on client-side JS (esbuild bundles, Tailwind CSS, optional jQuery plugin for column resize in Editor)

## External Dependencies
- PostgreSQL database reachable via `CONNECTION_STRING` (with `LISTEN/NOTIFY` capability for realtime, when implemented)
- Embedded NATS JetStream (no external service required)
- Client tooling
  - Tailwind CSS generation via `gotailwind` (Go tool)
  - esbuild for bundling TS in `web/libs`
  - Optional: `pnpm` if using the Lit example under `web/libs/lit`

## Developer Guide (Quick)
- Live dev: `go tool task live` → open http://localhost:8080
- Build binary: `go tool task build`; run with `go tool task run`
- Debug: `go tool task debug`
- Update web libs: `go run cmd/web/build/main.go [-watch]`
